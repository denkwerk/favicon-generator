- 🎯 **Ready in one command**: `favicon.ico`, an SVG favicon, a PNG and an Apple touch icon, plus the tags to link them
- 🧩 **Add what your site needs**: a web app manifest, a theme color, Windows tiles or legacy sizes, one option each
- 🎨 **Figma as a source**: pass a link to a component and it is exported through the Figma REST API
- ⚡️ **Native and self-contained**: a Rust binary, prebuilt for macOS, Linux and Windows; no sharp, no ImageMagick,
  no install scripts
- 🛠️ **One set of options everywhere**: CLI flags, `favicon.config.{ts,js,json}`, the Node.js API and the Nuxt module,
  typed by `defineConfig` and a JSON Schema
- 💚 **Nuxt module**: generates at build time, serves the files through Nitro, adds the tags, honours `app.baseURL`
  and caches the output

## Quick start

Try it without installing anything:

```bash
npx @denkwerk/favicon-generator -i ./logo.svg -o ./public/favicons
```

### CLI

```bash
pnpm add -D @denkwerk/favicon-generator
```

Use flags, a config file, or both:

Then paste the generated `public/favicons/favicon.html` into your `<head>`. Additionally, you can add a web app
manifest, a theme color, Windows tiles and more, see [What you get](#what-you-get).

### Nuxt

```bash
npx nuxt module add @denkwerk/nuxt-favicon-generator
```

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@denkwerk/nuxt-favicon-generator'],
  favicon: { input: './assets/favicon.svg' },
})
```

That's it: nothing is written to `public/`, and every page gets the `<link>` tags.

### Node.js API

```ts
import { generate } from '@denkwerk/favicon-generator'

await generate({ input: 'assets/favicon.svg', output: 'public/favicons' })
```

## What you get

One command gives you a complete, modern favicon set:

```text
public/favicons/
├── favicon.ico            16, 32 and 48 px in one file
├── favicon.svg            the SVG source, for modern browsers (SVG input only)
├── favicon-96x96.png      transparent
├── apple-touch-icon.png   180 px, on white, since iOS shows transparency as black
└── favicon.html           the tags below
```

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" type="image/svg+xml" href="/favicon.svg">
<link rel="icon" type="image/png" sizes="96x96" href="/favicon-96x96.png">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
```

Additionally, you can make your site an installable web app, color the browser UI, support pinned sites on Windows
or cover old devices. Each takes one option:

| Add | To get |
| --- | --- |
| [`themeColor`](#theme-color) | `<meta name="theme-color">` |
| [`manifest`](#web-app-manifest) | `manifest.json`, 192 and 512 px icons (optionally maskable) and `<link rel="manifest">` |
| [`windows`](#windows-tiles) | `browserconfig.xml`, tile images and `msapplication-*` tags |
| [`legacy`](#legacy-sizes) | 19 PNG sizes, sized Apple touch icons and a 7-frame `favicon.ico` for old devices |

## Configuration

### Where options go

Every option works the same in each place:

| Where | Example | Notes |
| --- | --- | --- |
| CLI flags | `--theme-color "#02969c"` | override the config file |
| `favicon.config.ts` · `.mts` · `.cts` | `defineConfig({ themeColor: '#02969c' })` | typed; evaluated with Node.js ≥ 22.18 |
| `favicon.config.js` · `.mjs` · `.cjs` | `export default { themeColor: '#02969c' }` | can compute values, read env vars or export an (async) function |
| `favicon.config.json` | `{ "themeColor": "#02969c" }` | read by the binary, no Node.js needed |
| Node.js API | `generate({ themeColor: '#02969c', … })` | the object is the whole config; files are not read |
| Nuxt | `favicon: { themeColor: '#02969c' }` in `nuxt.config.ts` | overrides `favicon.config.*`, group by group |

The CLI and the Nuxt module look for the config file in the current directory (Nuxt: `rootDir`) and its parents, up to
the nearest `package.json` or `.git`. Relative paths in it are resolved against its own directory. `--config <path>`
picks a file, `--no-config` ignores them. For editor support in `favicon.config.json`, add
`"$schema": "./node_modules/@denkwerk/favicon-generator/schema.json"`.

The additions are **groups**: set one to `true` for its defaults, or to an object with its options. Setting any of
its options or flags adds it too, and `false` or the matching `--no-…` flag leaves it out.

```ts
// favicon.config.ts, with every group
import { defineConfig } from '@denkwerk/favicon-generator'

export default defineConfig({
  input: './assets/favicon.svg',
  output: './public/favicons',
  pathPrefix: '/favicons/',
  themeColor: '#02969c',
  appleTouchIcon: { background: '#ffffff' },
  manifest: { name: 'My App', shortName: 'App', display: 'standalone', maskable: true },
  windows: { tileColor: '#02969c' },
  legacy: false,
})
```

### Input and output

| Option | Flag | Default | |
| --- | --- | --- | --- |
| `input` | `-i, --input`, or the first argument | *(required)* | SVG (best), PNG, JPEG or WebP, ideally square; or a [Figma link](#figma) |
| `output` | `-o, --output`, or the second argument | `favicons` | directory to write into |
| `pathPrefix` | `-p, --path-prefix` | `/` | URL the files are served from, used in all tags and the manifest |
| `overwrite` | `-y, --overwrite` | `false` | replace existing files instead of stopping |
| `snippets` | `--snippets` | `['html']` | head snippets: `html` (`favicon.html`), `json` (`favicon-head.json`), `nuxt` (`nuxt-head.ts`); `[]` or `none` for none |

### Theme color

```ts
themeColor: '#02969c'          // --theme-color "#02969c"
```

Adds `<meta name="theme-color">`, which colors the browser UI on mobile, and `theme_color` in the manifest.

### Apple touch icon

On by default: `apple-touch-icon.png`, 180 × 180 px and opaque.

| Option | Flag | Default | |
| --- | --- | --- | --- |
| `appleTouchIcon: false` | `--no-apple-touch-icon` | | leave it out |
| `appleTouchIcon.background` | `--apple-touch-background` | `#ffffff` | color behind transparent pixels |

### Web app manifest

Adds `manifest.json`, `favicon-192x192.png`, `favicon-512x512.png` and `<link rel="manifest">`, and makes your site
installable. The manifest contains exactly the fields you set; give it a `name` or `shortName` so browsers can offer
installing the app.

| Option | Flag | Manifest field / effect |
| --- | --- | --- |
| `manifest: true` | `--manifest` | a manifest with just the icons |
| `manifest.name` | `-n, --name` | `name` |
| `manifest.shortName` | `--short-name` | `short_name` |
| `manifest.description` | `--description` | `description` |
| `manifest.startUrl` | `--start-url` | `start_url` |
| `manifest.scope` | `--scope` | `scope` |
| `manifest.display` | `--display` | `display`: `fullscreen`, `standalone`, `minimal-ui` or `browser` |
| `manifest.backgroundColor` | `--background-color` | `background_color`, also behind maskable icons |
| `manifest.maskable` | `--maskable` | adds `favicon-maskable-{192,512}` icons: the image at 60 % on `backgroundColor`, so Android's round masks don't cut into it |
| `manifest.crossorigin` | `--manifest-crossorigin` | `crossorigin` on the `<link>`, e.g. `use-credentials` |

Any manifest flag turns the manifest on, e.g. `favicon-generator -i logo.svg -o out --name "My App"`.

### Windows tiles

For sites pinned to the Windows start menu: `browserconfig.xml`, 70, 150 and 310 px tiles, and the `msapplication-*`
tags. Turn on with `windows: true` / `--windows`, or by setting a color:

| Option | Flag | |
| --- | --- | --- |
| `windows.tileColor` | `--tile-color` | `msapplication-TileColor` |

### Legacy sizes

`legacy: true` / `--legacy` adds what old browsers and devices look for: PNGs in 19 sizes (16 to 512 px), Apple
touch icons in 120 and 152 px with `-precomposed` copies, the matching `<link>` tags, and a `favicon.ico` with 7 frames
up to 256 px. Modern browsers don't need them.

### Figma

Use a link to a component as `input`; it must contain a `node-id` (right-click the component → *Copy link*). The
node is exported as SVG through the [Figma REST API](https://developers.figma.com/docs/rest-api/), which needs a
personal access token with the `file_content:read` scope:

| Option | Flag / env var | |
| --- | --- | --- |
| `figmaToken` | `--figma-token`, `FIGMA_TOKEN` | the token; prefer the env var over committing it |
| `figmaTokenFile` | `--figma-token-file`, `FIGMA_TOKEN_FILE` | a (gitignored) file containing the token |

<details>
<summary><b>Upgrading from 0.1</b></summary>

<br>

0.2 generates the minimal set by default; add `legacy: true` for the old sizes. The app options moved into groups,
and the old names are rejected with a hint:

| 0.1 | 0.2 |
| --- | --- |
| `appName`, `appShortName`, `appDescription` | `manifest.name`, `manifest.shortName`, `manifest.description` |
| `startUrl`, `scope`, `display`, `manifestCrossorigin` | `manifest.startUrl`, `manifest.scope`, `manifest.display`, `manifest.crossorigin` |
| `backgroundColor` | `manifest.backgroundColor`, or `appleTouchIcon.background` for the touch icon |
| `tileColor` | `windows.tileColor` (which also adds `browserconfig.xml`) |
| `iconPurpose: 'any maskable'` | `manifest.maskable: true` (separate maskable icons) |
| `--app-name` | `--name` |
| `snippets` default `['html', 'nuxt']` | `['html']` |

## Contributing

Requires Node.js ≥ 22.18, pnpm and a Rust toolchain.

```bash
pnpm install
pnpm turbo run build lint test typecheck   # everything: crate, npm packages, tests and the Nuxt examples
pnpm turbo run generate                    # run the CLI and Node.js API examples
pnpm --filter example-nuxt dev             # the Nuxt example in dev mode
```

To try the Figma export, copy [`.env.example`](.env.example) to `.env.local` (gitignored) and set `FIGMA_TOKEN`. In CI,
the Figma example runs when a `FIGMA_TOKEN` repository secret is set.

<details>
<summary><b>Releasing</b></summary>

<br>

Releases are automatic: every push to `main` runs the [release workflow](.github/workflows/release.yml), and
[semantic-release](https://semantic-release.gitbook.io) decides from the [Conventional Commits](https://www.conventionalcommits.org)
since the last tag whether to release and which version:

| Commit | While on 0.x | Example |
| --- | --- | --- |
| `fix:`, `perf:`, `feat:`, `docs(readme):` | patch, `0.1.0` → `0.1.1` | `feat(nuxt): add a themeColor option` |
| breaking (`feat!:`, `BREAKING CHANGE:` footer) | minor, `0.1.0` → `0.2.0` | `feat(cli)!: rename --out to --output` |
| `chore:`, `docs:`, `ci:`, `test:`, `refactor:`, … | no release | |

`docs(readme):` releases so that README changes reach the npm package pages. PRs are squash-merged, so their title
is the commit message; the [PR title check](.github/workflows/pr-title.yml) makes sure it is a Conventional Commit.
To leave 0.x, remove the `releaseRules` for breaking changes and features in [`release.config.mjs`](release.config.mjs).

A release runs CI, builds the binaries, publishes both npm packages, commits the version bump and
[`CHANGELOG.md`](CHANGELOG.md) (`chore(release): x.y.z`), tags it and creates a GitHub release with the archived
binaries. Pushes to a `next` branch publish prereleases (`0.2.0-next.1`) to the `next` dist-tag.

Running the workflow manually (*Actions → Release → Run workflow*) is a dry run that builds and packs everything.
With a tag (`v0.2.0`), it publishes that existing release to npm again, e.g. after a failed publish; versions
already on npm are skipped.

npm authentication uses [trusted publishing](https://docs.npmjs.com/trusted-publishers): npm accepts publishes of
both packages only from `release.yml` in this repository, in the `npm` GitHub environment. There is no npm token.

</details>
